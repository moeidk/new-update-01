# راهنمای استقرار خودکار KeepPass Vault

از این نسخه به بعد **هیچ دیپلوی دستی لازم نیست.** کافی است کد را در گیت‌هاب Push کنید:

| کجا Push می‌کنید | چه اتفاقی می‌افتد |
| :--- | :--- |
| برنچ `main` (یا Merge یک PR در `main`) | تست ← بیلد ← انتشار خودکار روی **سایت اصلی (Production)** |
| هر برنچ دیگر (مثلاً `feature/x`) | تست ← بیلد ← انتشار روی **نسخه آزمایشی (Staging)** با آدرس جدا |
| Pull Request | فقط تست و بیلد (بدون انتشار) |

کل فرایند معمولاً **۱ تا ۲ دقیقه** طول می‌کشد (بیشترش نصب پکیج‌ها و بیلد است؛ خود استقرار روی Cloudflare چند ثانیه است و **بدون قطعی** انجام می‌شود). کاربرانی که برنامه باز است حداکثر ظرف حدود **یک دقیقه** بنر «نسخه جدید KeepPass منتشر شد» را می‌بینند و با یک کلیک به‌روز می‌شوند. داده‌ها در مرورگر کاربر می‌مانند و پاک نمی‌شوند.

---

## راه‌اندازی یک‌باره (فقط بار اول)

### ۱. ساخت توکن در Cloudflare
1. وارد [dash.cloudflare.com](https://dash.cloudflare.com) شوید ← آیکون پروفایل ← **My Profile** ← **API Tokens** ← **Create Token**.
2. قالب **Edit Cloudflare Workers** را انتخاب کنید (دسترسی‌های Workers Scripts و Workers KV Storage را دارد).
3. در بخش Account Resources حساب خودتان را انتخاب کنید و توکن را بسازید. مقدار آن را کپی کنید (فقط یک‌بار نمایش داده می‌شود).

### ۲. ثبت توکن در گیت‌هاب
در مخزن گیت‌هاب: **Settings ← Secrets and variables ← Actions ← New repository secret**

| نام | مقدار | لازم است؟ |
| :--- | :--- | :--- |
| `CLOUDFLARE_API_TOKEN` | توکن مرحله قبل | ✅ بله |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID (ستون راست داشبورد Cloudflare) | فقط اگر چند حساب دارید |

### ۳. یک Push
همین. در اولین استقرار، فضای ذخیره ابری (KV) به‌صورت خودکار ساخته و به Worker وصل می‌شود.
آدرس سایت در تب **Actions** گیت‌هاب، در خلاصهٔ اجرای آخر نمایش داده می‌شود (معمولاً `https://keeppass-vault.<نام-شما>.workers.dev`).

> برای «کاملاً خودکار» بودن، روی محیط `production` در **Settings ← Environments** گزینهٔ *Required reviewers* را فعال **نکنید**. اگر خواستید قبل از هر انتشار تأیید دستی بدهید، همان گزینه را فعال کنید.

> اگر دامنهٔ اختصاصی دارید: Cloudflare ← Workers & Pages ← `keeppass-vault` ← Settings ← Domains & Routes ← Add Custom Domain.

## روال روزمره

```bash
# کار روی یک برنچ آزمایشی → روی Staging منتشر می‌شود
git checkout -b feature/new-thing
git commit -am "feat: توضیح تغییر"
git push origin feature/new-thing

# وقتی راضی بودید → Merge در main → روی سایت اصلی منتشر می‌شود
```

متن کامیت‌ها به‌عنوان «تغییرات این نسخه» در بنر به‌روزرسانی به کاربران نشان داده می‌شود؛ پس پیام کامیت را خوانا بنویسید.

اگر لازم شد دستی منتشر کنید: تب **Actions ← Build & Deploy ← Run workflow** و انتخاب محیط.

## اجرای محلی

```bash
npm ci --legacy-peer-deps
npm run dev        # رابط کاربری روی http://localhost:3000
npm run dev:api    # در ترمینال دوم: API (Worker) روی پورت 8787، با KV محلی
npm run preview    # بیلد کامل و اجرای دقیقاً همان چیزی که روی Cloudflare می‌رود
```

## معماری و امنیت (خلاصه)

- **بدون سرور سنتی:** فرانت‌اند و API هر دو روی Cloudflare Workers اجرا می‌شوند (`worker/index.ts`). سرور Express قبلی هیچ‌وقت روی Cloudflare اجرا نمی‌شد و حذف شد.
- **رمزنگاری سمت کاربر:** همه‌چیز در مرورگر با AES-256-GCM رمز می‌شود. کلید با PBKDF2-SHA256 و ۶۰۰٬۰۰۰ تکرار از رمز اصلی ساخته می‌شود (حساب‌های قدیمی ۱۰۰٬۰۰۰؛ با تغییر رمز به ۶۰۰٬۰۰۰ ارتقا می‌یابند).
- **وام‌ها، هاست‌ها و توکن ربات تلگرام** هم حالا رمزنگاری‌شده ذخیره می‌شوند (قبلاً متن ساده بودند). مهاجرت در اولین ورود خودکار انجام می‌شود.
- **فیس‌آیدی / اثر انگشت:** کلید گاوصندوق دیگر به‌صورت خام در `localStorage` نیست. روی دستگاه‌های جدید (iOS 18+، اندروید/کروم جدید) کلید با قابلیت WebAuthn PRF مستقیماً به حسگر بیومتریک قفل می‌شود؛ در مرورگرهای قدیمی‌تر با یک کلید غیرقابل‌استخراج در IndexedDB محافظت می‌شود.
- **پشتیبان ابری:** سرور فقط داده رمزشده + هش یک «توکن مالکیت» مشتق‌شده از کلید را نگه می‌دارد. بدون رمز اصلی هیچ‌کس نمی‌تواند نسخه ابری را بخواند یا بازنویسی کند. پس از ۲۰ تلاش ناموفق، آن نام کاربری ۱۵ دقیقه قفل می‌شود.
- **هدرهای امنیتی** (CSP سخت‌گیرانه، منع iframe و…) در `public/_headers`.

### نکته برای کاربران فعلی بعد از این آپدیت
- ورود با رمز مثل قبل کار می‌کند.
- اگر فیس‌آیدی فعال بوده، **یک‌بار با رمز عبور وارد شوید** تا ورود بیومتریک دوباره فعال شود. برای قوی‌ترین حالت (PRF)، آن را در تنظیمات ← امنیت یک‌بار خاموش و روشن کنید.
- همگام‌سازی ابری قبلاً روی سایت اصلی کار نمی‌کرد؛ اکنون فعال است. یک‌بار از تنظیمات ← پشتیبان و داده‌ها «همگام‌سازی ابری» را بزنید.
